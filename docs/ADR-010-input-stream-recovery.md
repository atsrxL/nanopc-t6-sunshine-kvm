# ADR-010：低延迟输入通道与串流断线缓冲

日期：2026-09-24　状态：已部署T6，待客户端实测

## 背景

用户反馈：画面稳定120fps，但大幅移动时鼠标延迟明显；客户端断开重连过于激进。

排查结论：

- 视频路径逐帧发送，发送队列高水位为1，采集到入队约9ms，不是延迟来源。
- 输入路径每个事件新建一次到 kvmd 的 HTTP 连接并串行等回复（T6实测单次约1.9ms中位），相对移动还被拆成±127小块逐个请求。大幅移动时事件排队，延迟随之累积。原版 Sunshine 直接写本机 uinput，不存在此开销。
- 近期断开由 worker 的 `HDMI frame timeout` / `DQBUF: Invalid argument` 直接致命触发；bridge 另有1.5s卡顿、200ms帧龄、发送队列满即断开三条硬规则。

## 决定

1. **HID**：会话握手时打开一条持久 kvmd `/ws?stream=0` WebSocket，按 kvmd 原生二进制事件发送（键1、按钮2、绝对3、相对批量4带squash、滚轮5），不等逐条回复。kvmd 按顺序处理。结束时用 ping(0)/pong(0xff) 确认此前事件已处理，再关闭流并走原有 HTTP release。WebSocket 不可用时回退到逐事件 HTTP。事件内容不记录。T6实测WS确认往返中位0.3ms。
2. **worker 采集恢复**：采集超时、DQBUF错误、周期性源检查失败时，在5秒窗口内重开采集和编码器，保持同一协商模式，AU序号接续，强制IDR。源模式变化仍直接退出，交给客户端按新模式重连。
3. **bridge**：卡顿断开阈值1.5s→7s（覆盖worker恢复窗口）；取消200ms帧龄断开；发送队列50ms内挤不进则丢弃该帧并请求IDR，直到IDR到达前丢弃依赖帧（与上游 Sunshine 丢包后靠IDR恢复一致）。日志新增 `dropped_for_idr`。

## 补充：鼠标报告限速（2026-09-24）

用户反馈：大幅拖动窗口晃动时，鼠标停下约1秒后窗口才停。原因：kvmd 的 OTG 鼠标进程每约4ms写一个USB报告（T6实测约245个/秒），它的内部队列不合并事件。改用 WebSocket 后发送不再受阻，1000Hz 鼠标的事件全部进入 kvmd 队列，积压后迟到回放。

改法：`KvmdStream` 对鼠标报告按4.2ms间隔限速，积压留在 rkmoon_hid 自己的队列里，相邻移动在那里合并（绝对模式取最新位置，相对模式累加位移），按键/按钮顺序不变。键盘是独立USB设备，不限速。

T6实测（1000Hz绝对坐标注入1.5秒）：旧版最后输入后4098ms才写完；新版7ms。backend.py `bbfd5c7d…` 已部署，备份在 `/root/agent.backup/rkmoon-r4-20260924/`。客户端主观手感待用户确认。

## 补充：按键丢失（2026-09-24）

用户反馈：偶尔丢键盘/鼠标点击。在Znas被控机用低级键盘/鼠标钩子计数（钩子吞掉事件，不影响桌面），T6经WebSocket注入：

- 鼠标左键300次（快速、按住20ms、夹杂移动）：300/300，未丢。
- 键盘F20按下后立即抬起200次：只收到109次；间隔1ms 193、2ms 171、4ms以上200。kvmd日志无写入失败，USB未断开。原因：键盘报告间隔短于约4ms时，被控机来不及轮询，按下与抬起两份报告只有后一份生效，这次按键就消失了。旧版逐条HTTP请求每条约2ms，也会偶发。

改法：键盘报告与鼠标一样按4.2ms间隔发送（各自独立计时）。修复后900次0～2ms间隔的按键全部收到。backend.py `df5adb7c…` 已部署，备份在 `/root/agent.backup/rkmoon-r6-20260924/`。
