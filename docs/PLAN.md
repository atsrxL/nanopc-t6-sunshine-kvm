# 优化后的执行计划

## 不变的目标

HDMI 源电脑 → T6 HDMI RX → V4L2 → MPP HEVC/H264 → Sunshine 会话与网络发送 → 原版 Moonlight。Moonlight 输入经过上游解密/验证后，经独立桥接与现有 kvmd 到被控电脑 USB HID。首目标真实 1920×1080p60，SDR8、单客户端；不保证低于某个毫秒数，也不保证 HEVC 比 H264 更低延迟。

后续原生 1440p60、4K60；HDR/10-bit、AV1、4K120、手柄、音频采集、绝对鼠标、ATX、USB 存储、公网、浏览器和客户端修改不进入第一轮。

## 相比原计划的收敛

**将 P0 拆为“源码决策”与“本地构建/硬件事实”两道门。** 前者已做，后者仍未通过。不会因为查到一个 HEVC enum 就宣称 HDMI 接入成功。

**固定路线 B，不再并行维护两条视频栈。** worker 负责硬件资源；Sunshine 只增加编码包与控制适配。保留上游网络、安全与配对实现，避免 FFmpeg MPP 支持情况成为架构前提。

**显式分离三个面：视频、输入、安全控制。** worker 由每个获准会话私有启动；输入桥接持独占租约，不随着编码线程卡死而失去释放机制。音频完全不采集，P2 必须测试该策略与目标客户端兼容。

**将硬件假设改为拒绝条件。** 尺寸/fps/颜色/布局未知即报错；不能自动改 EDID/S_FMT/源模式。CPU 像素拷贝必须明确授权和报告；软件视频编码永不回退。1080p 严格直接导入对齐不满足时优先做显式拷贝基线，而不是虚称零拷贝。

**减少丢参考帧风险。** V4L2 允许丢未编码 raw；从 MPP 输出后不再任意丢 P 帧。私有 socket 一帧一 credit，Sunshine 待发送队列限 2；超时关闭会话，再从 IDR 新建流。暂不做“拥塞时扔 P 帧继续播”的激进优化。

**先视频闭环，再输入接管。** 当前旧记录为绝对 USB 鼠标，必须单独解决授权，不让 P3 阻塞 P1/P2 或偷偷改 gadget。

## 阶段与停止条件

| 门 | 工作 | 必须拿到的证据 | 失败时 |
|---|---|---|---|
| P0-source | 固定上游/接口/许可/专用 headless 路径 | ADR、固定源码与补丁生成器 | 更新决策，不铺开重写 |
| P0-build | 独立 MPP worker 和完整 Sunshine 真实构建 | SDK/工具链版本、二进制 SHA256、链接依赖、补丁 diff、全部离线测试 | 修构建；不拿假头文件/替代编码冒充 |
| H0 | 设备只读基线、客户端能力、占用者与授权窗口 | timings/plane/stride/format/VUI来源、内核/MPP/内存/散热、客户端硬解信息 | 缺项保持未知，禁止改内核/EDID/UDC补齐 |
| P1 | HDMI→HEVC/H264 独立硬编码各至少60秒 | 连续 AU/CSV、ffprobe+完整解码、强制IDR、视觉检查、路径/CPU/温度/内存 | 结束 worker、确认采集可重开，恢复旧所有权 |
| P2 | 原版 Moonlight video-only各10分钟 | 配对、尺寸协商、客户端实际硬解、无持续延迟增长、重连、丢包恢复 | 不开输入，保留私有日志/停止新实例 |
| P3 | 相对 USB 输入 | 相对descriptor/kvmd状态、目标电脑真实事件、组合键/滚轮/按住释放、断网/退出/异常释放 | 锁住输入租约，禁止重新接管直到释放完成 |
| P4 | 同条件旧方案/新HEVC/新H264比较 | p50/p95/p99+样本数、客户端统计、物理同框/高速摄影、码率与画质条件 | 不比较不同时钟和不同负载的单个数字 |
| P5 | 原生1440p60然后4K60，2h然后8h | 每一层单独通过、CPU/温度/内存、HDMI变化、重连、延迟漂移 | 降回已通过模式；不得隐式缩放/虚报分辨率 |

## 实验设计

P1 启动 `--gop 120 --idr-at 1`，强制请求应出现在约一秒、而不是正好两秒 GOP 边界；保存 IDR序列与参数集。默认 60fps 只适配实测接近60Hz信号，59.94可用fps-x1005994；不接受30fps源冒充60帧，不能复用重复帧通过验收。

P2 先有线 LAN、1080p60、HDR关闭、HEVC硬解明确启用；再明确选择H264。HEVC失败不在一个会话里偷换codec，应由协商/重连明确选择H264或报错。无音频策略测试失败时另做最小协议兼容设计，不宣称已采HDMI声音。

P3 中段拔网、杀 Sunshine、杀桥接、重启本实例、kvmd暂时不可用分别测试。旧VNC输入/网页输入在窗口内要避免同时使用；本地锁不能强制其他程序合作。USB物理断开/kvmd不可达造成无法送达release时报告失败而不是“保证无卡键”。

P4 按 CLOCK_MONOTONIC 记录服务器阶段；完整 HDMI capture latency、输入→显示、显示→显示必须分别测量。不直接相减两台机器未校准时钟。受限带宽/丢包仅在用户授权的隔离测试环境进行；源P帧依赖损伤与frame age一起记录。

## 权限/回滚门

任何需要停止旧采集、调整设备ACL、增加相对HID、安装工具链/系统包、切换EDID、变更内核/CMA的操作，单独列出最小范围与回滚并取得授权。本包不会自动做上述操作。每次停止新实例确认没有残余worker/HID租约，然后才按原用户方式恢复旧采集。没有授权就推进可离线完成的部分，不能默默越界。
