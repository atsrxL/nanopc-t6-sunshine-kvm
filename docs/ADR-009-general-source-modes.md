# ADR-009: 通用 HDMI 源模式与整数客户端帧率映射

2026-09-24。替代 ADR-006 的1440p90专用白名单；固定Sunshine/MPP版本不变。

服务端允许偶数宽高，宽64..3840、高64..2160，fps_x100为100..12010。
吞吐预算为 width * height * fps_x100 <= 3840 * 2160 * 6010，使用64位乘法。
这只是配置接纳范围，不宣称每一种模式已经真实HDMI/MPP/客户端验收。
既有 allow_high_resolution 门保留：关闭时专用Sunshine仅接受1920x1080。
legacy allow_1440p90_experiment / CLI参数仍可解析，但不再决定配置合法性。

源模式来自只读 QUERY_DV_TIMINGS，保持250ms缓存，不新增 G_FMT、EDID或采集操作。
客户端整数字段仅在尺寸与ready源一致、整数fps等于源四舍五入fps时，映射为源精确fps_x100。
例如60→59.94、120→119.88、76→75.50；显式非整数帧率请求不覆盖，尺寸/整数fps不匹配也不覆盖。
实际采集继续核对源尺寸、0.15Hz误差和像素布局；没有缩放、软件编码、桌面抓屏兜底。
GOP使用实际有效fps四舍五入并限制1..120。MPP保持精确百分之一Hz分子/100分母。

HEVC等级继续同时按图像面积、像素率和码率预算选择4.1/5/5.1。
H264等级除宏块每秒预算外，新增每帧宏块数限制：超过8704不能标4.2，
避免4K低帧率被错误标记为4.2；现有最大尺寸/吞吐在5.2能力预算以内。
密码、输入加密、租约、绝对/相对鼠标安全与释放保护不变。

验收分开记录：配置/metadata/codec等级离线测试，ARM64完整worker/server链接，
生产HTTP合成验证，真实HDMI与BetterDisplay自定义模式、客户端验证。
本代理只实现和构建，设备部署与真实模式切换归父代理；未获硬件证据前保持未测试。

低帧率限制：1fps仅表示配置可接纳及等级预算合法。既有capture约1000ms等待、
bridge 1.5s停滞时限本次不改；1fps在抖动下的稳定性未证明，需另行做有界且随帧周期调整的超时验证。
当前硬件验收优先30..120fps，不能用配置通过替代低帧率实机通过。

实机结果（2026-09-24，见 results/20260924-general-modes/HARDWARE-SWEEP.md）：
八个EDID模式中，除1080p120外全部真实采集+硬编+独立解码通过；1440p120/1600p120/1280p90/4K走DMA-BUF直通。
1080p因行高非16倍数只能CPU拷贝，1080p120仅约108fps（掉帧约10%），未通过；拷贝循环已去掉整缓冲memset。
